# АРУ: обновление через личный кабинет по понедельникам

Правило владельца от 09.10.2026: API нет и не ожидается; обновлять один раз
в неделю, по понедельникам. Расписание: 10:00, Europe/Moscow. Последний
успешный прайс работает до успешной замены, без срока истечения 24 часа.
При пропуске обновления данные не удаляются и товары не скрываются.
Наличие означает статус на дату последнего полного обхода.

## Сбор

Использовать навык computer-use и только поддерживаемые CUA API для Chrome.
Не извлекать cookies или токены и не переносить авторизацию на сервер.
Не обходить вход: при истечении сессии запросить новый код у владельца.
Не обращаться к менеджеру и не оформлять заказы.

Для каждого запуска создать новую папку
`../outputs/aru-refresh-YYYYMMDD-HHMM/pages`. Не смешивать разные недели.
Открыть авторизованную страницу `https://aru.ooo/vse-tovary/`.
Читать карточки через `tab.playwright.evaluate` с чистой функцией из
`scripts/aru_account_dom.js`; файл прочитать через разрешённый локальный
I/O внутри CUA REPL. Функция читает только DOM, без сетевых запросов.

На каждой странице подтвердить `authenticated: true`, фактический URL,
номер страницы, неизменное общее число страниц и непустые карточки.
Сохранять ответ плюс `page` и `captured_at` (ISO UTC) в `001.json` и далее.
Страницы `?page=N` выведены реальной пагинацией сайта. Размер порции — 30.
Продолжать до последней страницы; при задержке проверить состояние вкладки,
потом восстановить её или создать новую в том же выбранном Chrome.
Использовать короткие порции работы с промежуточным сохранением. При
устойчивом сбое запросить перезапуск Chrome и продолжить с первой
несохранённой страницы текущего запуска. Не объявлять частичный обход полным.

## Проверка и установка

Из локального проекта Авито:

```text
python avito-bridge/scripts/refresh_aru_account.py --pages-dir <новая папка>/pages --output-dir <новая папка>
```

Команда требует полного авторизованного обхода; все исходные страницы
нового сбора должны быть сделаны в последние 24 часа. Это проверка целостности
нового сбора, а не срок действия установленного прайса. Товар, перемещённый
между страницами при изменении наличия, учитывается по более позднему
наблюдению с журналом; дубли внутри страницы отклоняются.
Рабочие строки: строго «В наличии», положительная персональная цена.
Цена контента = исходная цена ×1,10, целые рубли округляются вверх.

После проверки JSON передаётся по существующему SSH alias `sprintbox-itp`.
Серверный `scripts/install_aru_snapshot.py` сохраняет резервные копии и
заменяет только `/opt/content-factory/state/prices/aru-catalog.json` и
`/opt/avito-bridge/runtime/aru/catalog.json`. Проверяются оба загрузчика;
при ошибке оба предыдущих снимка восстанавливаются. Код, профильные выборки,
категории, боевой фид и объявления процедура не изменяет. Затем обновляются
локальные копии. Применение прайса не требует перезапуска контент-завода:
источник читается при поиске/задаче. Отчёт `refresh-result.json` содержит
дату прайса, количества добавленных/удалённых товаров и изменённых цен.

## Отображение и сбои

Контент-завод `/sources`: количество, дата прайса и понедельничный график.
После 7 дней появляется отметка о задержке, поиск продолжает работать.
Avito Studio: дата прайса и график в строке состояния; подсказка товара
указывает, что наличие относится к дате сбора. Экспорт содержит
`supplier_updated_at`, `account_price`, `content_price_preview`.

Автоматизация использует этот локальный компьютер и доступный Chrome;
для запуска нужны включённый компьютер и работающий Codex. Если браузер,
SSH или вход недоступны, сохранить старый прайс и сообщить о необходимом
действии. При неизменных данных не присылать сообщения. После значимого
изменения дать один краткий итог с датой и количествами. Не создавать
автоматическую публикацию, новые объявления или платный контент.
