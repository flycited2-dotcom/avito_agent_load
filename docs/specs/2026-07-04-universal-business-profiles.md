# Спека: Универсальные профили бизнеса (avito-bridge + avito-studio)

Дата: 2026-07-04. Статус: согласована владельцем устно («универсальный солдат» под любые
товары; первый новый профиль — ритуальные венки/корзинки).

## 1. Проблема

Связка avito-bridge (фид) + avito-studio (GUI) + фотоагент (карточки) работает только для
кондиционеров из БД oasis. У владельца минимум два бизнеса (кондиционеры, ритуальные
венки/корзинки) и потоки КБТ/МБТ; каждый новый вид товара сейчас требует программиста.
Нужно: добавление нового бизнеса = новый конфиг + свои эталоны/шаблоны, БЕЗ правки кода.

## 2. Критерии успеха (наблюдаемые)

- В студии есть переключатель профиля; выбор «Венки» показывает каталог ritualb2b
  (55 товаров с сайта), выбор «Кондиционеры» — прежний каталог oasis. Ничего не сломано:
  кондиционерный фид продолжает публиковаться без изменений (это профиль №1).
- Фид венков принят Автозагрузкой ВТОРОГО аккаунта Avito (отчёт v4 uploads: ≥1 объявление
  published) — это «done» всего проекта.
- Карточка венка генерится фотоагентом в стиле, заданном эталонами профиля (режим ritual
  УЖЕ существует в фотоагенте — переиспользуем).
- Текст объявления венка собирается по шаблону профиля (не по кондиционерному генератору).

## 3. Объём

### IN
- `BusinessProfile`: один YAML на бизнес (источник, ключи Avito-аккаунта, категорийные
  теги XML, правила цен, шаблон описания, режим карточек фотоагента, город/контакты).
- Адаптеры источников: `oasis_db` (есть), `ritualb2b_site` (products.js сайта — источник
  подтверждён: 55 товаров, 31 венок + 24 корзинки, уникальные descShort/descLong).
- Категорийный слой: base_tags уже конфигурируемые; вынести кондиционерные
  AirConditionerType/SubType в опциональный category-mapping профиля.
- Шаблоны описаний per профиль (для венков descLong с сайта уже готов — шаблон тривиален).
- Студия: селектор профиля, конфиг-пути и SSH-цели из профиля.
- Второй Avito-аккаунт: отдельные ключи API, отдельный XML-фид, отдельный upload-URL.

### OUT (сознательно не делаем сейчас)
- Мульти-аккаунт ChatGPT в фотоагенте (владелец сам разводит аккаунты; техчасть — отдельная
  задача после стабилизации квоты).
- Новые режимы карточек (ritual уже есть; новые эталоны кладёт владелец).
- Автоматический парсинг ПРОИЗВОЛЬНЫХ сайтов («любой сайт» — не сейчас; сейчас конкретный
  адаптер products.js).
- Изменения контент-завода и Telegram-каналов.
- Excel-источник (заготовка есть в content-factory; подключим третьим профилем, когда
  появится реальный бизнес-кейс).

## 4. Ограничения

- Кондиционерный фид — боевой; любые рефакторинги без изменения его XML (побайтово, кроме
  осознанных правок) — сверка снапшотом до/после.
- Автозагрузка Avito: категория для ритуальных товаров должна поддерживаться фидом —
  подтвердить ДО написания адаптера (риск №1).
- Один VPS (213.109.202.45); feed венков — отдельный файл/URL на том же nginx.
- Стек прежний: Python, pydantic/lxml, PySide6; без новых тяжёлых зависимостей.

## 5. Риски

| Риск | Ранний сигнал | Запасной ход |
|---|---|---|
| Автозагрузка не поддерживает категорию венков | Проверка формата в ЛК 2-го аккаунта на шаге 1 | Публикация через API объявлений (не Автозагрузку) или ближайшая поддерживаемая категория («Для дома и дачи») |
| Ключи 2-го аккаунта не дадут/задержат | Нет ключей к шагу 5 | Всё до шага 5 делается без ключей; фид венков валидируем локально по XSD/формату |
| Рефакторинг ломает кондиционерный фид | Снапшот-дифф XML в тестах падает | Профиль №1 = текущий config.yaml как есть; никакой миграции данных |

## 6. Что нужно от владельца

1. **Ключи API второго аккаунта Avito** (client_id/secret Автозагрузки) — к шагу 5.
2. **Категория**, в которой конкуренты размещают венки на Avito (или скрин из ЛК
   Автозагрузки со списком категорий) — к шагу 1.
