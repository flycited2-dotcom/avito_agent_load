# Защита снятых объявлений, 04.11.2026

Владелец сообщил о повторном появлении снятой техники. Проверка сервера
20:09–20:18 МСК выявила работающий пятиминутный таймер, который не сохранял
снятия без ранее замеченного состояния active. При первом наблюдении removed,
пропущенном активном периоде или снятии после модерации состояние наблюдений
обновлялось, но стоп не создавался. Кроме того, служба не включала архивную
защиту, а процедура renewal разрешала возвращать спорные archive_hold.

Исправлено:

- Текущий removed сохраняется независимо от предыдущего наблюдения.
- С --hold-archive удерживается уже обнаруженный old без доказанного истечения
  срока, включая ранее пропущенные снятия. Обычный old с доказанным истечением
  срока не превращается в ручное снятие.
- Если core API говорит removed, а отчёт загрузки указывает истечение срока,
  создаётся archive_hold с expiration_evidence=true. Это спорный случай для
  проверки, а не доказанное ручное снятие и не разрешение на автопродление.
- Renewal больше не освобождает archive_hold. Подтверждённые прежние ручные
  стопы не заменяются. Имена ID и артикулы не меняются.
- Архивная защита включена в установленной службе и проверке перед сборкой.

Исправление установлено точечно в manual_stop.py, renewal.py, службе
avito-manual-stop-sync и /opt/avito-bridge/run.sh. Резервные версии кода,
unit-файла, фида и реестров:
/opt/avito-bridge/state/manual-stop-fix-20261104. Предпросмотр выполнялся на
копиях состояния с реальным чтением API до изменения рабочего фида.

Применение 20:17 МСК: из фида исключено 11 ID, осталось 89. Десять из них уже
имели removed или неистёкший old; чайник Midea MK-9095 (nikita-00-00001222,
Avito 8305548778) закреплён ручным стопом по сообщению владельца. В числе
удержанных аэрогрили Midea MAF-TN40D, Sakura SA-7684W и BQ GR2005. В квитанциях
этих трёх указан истёкший срок, поэтому причина сохранена как спорная.
Полный список и причины лежат в серверном plan.json рядом с резервной копией.

Повторный запуск 20:18 МСК: added=0, suppressed=93, фид остался побайтово
прежним. Все 89 оставшихся объявлений совпали с резервной копией по XML
после исключения пробельного форматирования. Стопы не были освобождены,
публикация новых карточек осталась на паузе владельца (с 13 октября).

Важно: это подтверждение исправленного серверного фида, а не нового приёма
Avito. На момент проверки API возвращал последнюю загрузку 625161366 от
30.10.2026 19:41 UTC; получение нового фида площадкой ещё не подтверждено.
Принудительная загрузка и платная реактивация не запускались.

Проверки: 54 профильных теста прошли. В широком прогоне 699 тестов прошли,
четыре теста cards_pipeline упали из-за SQLite URI с Windows-префиксом
длинных путей. Отдельный запуск всех 27 тестов cards_pipeline без этого
префикса прошёл. Таким образом, проверены все 703 сценария в подходящих
для Windows режимах. Существующие посторонние изменения checkout не входили
в это исправление и не выкладывались на сервер.
